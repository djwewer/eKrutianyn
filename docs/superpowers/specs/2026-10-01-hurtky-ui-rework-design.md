# Доопрацювання інтерфейсу гуртків — дизайн

**Дата:** 2026-10-01

## Контекст і проблема

Щойно домерджено архівацію (`archivedAt`/`archivedById` на `Hurtok`,
`PATCH /hurtky/:id/archive`). Зараз інтерфейс гуртків складається з:

- `/hurtky` — картковий список усіх гуртків куреня (чи лише призначених,
  якщо actor — виховник), клік веде на окрему сторінку.
- `/[kurinNumber]/hurtky/[slug]` — сторінка одного гуртка: назва, банер
  "Архівовано" (якщо архівований), кнопка "Архівувати гурток", таблиця
  членів.

Користувач показав скріншот зі стороннього/legacy інструменту — акордеон
зі списком гуртків, де кожен розгортається і показує впорядника, кнопки
дій і повну таблицю членів прямо в списку. Поточний двосторінковий підхід
(список → окрема сторінка) визнано неінтуїтивним.

Початковий запит включав також аватар-сильветку гуртка (кругла
"нашивка"); відкинуто користувачем як таке, що не несе цінності — поза
межами цієї фічі.

## Що змінюється

1. **Налаштування гуртка** — кнопка "Налаштування" на сторінці/в
   розгорнутому рядку гуртка відкриває модальне вікно для зміни
   виховника, чотирьох посад-"діловодів" гуртка, дати заснування, і
   розформування гуртка.
2. **`/hurtky` стає акордеоном** — кожен рядок розгортається inline,
   показуючи те, що раніше було на `/[kurinNumber]/hurtky/[slug]`.
   Декілька рядків можуть бути розгорнуті одночасно.

`/[kurinNumber]/hurtky/[slug]` лишається в коді без змін — для прямих
посилань (наприклад, зі старих закладок). Основний щоденний шлях —
через акордеон на `/hurtky`. Додавання юнака лишається можливим і з
гуртка (кнопка "Додати юнака/чку" в розгорнутому рядку, як і зараз), і
з `/users/new` (сторінка "Люди") — обидва шляхи вже існують і не
змінюються.

## Модель даних

```prisma
model Hurtok {
  // ...існуючі поля
  foundedAt DateTime?
}
```

Нове nullable поле, без бекфілу (існуючі гуртки матимуть `foundedAt =
NULL` — звʼязковий заповнює вручну за потреби). Міграція потрібна в
обох базах (`plast_dev` і окремо `plast_test` командою `DATABASE_URL=...
npx prisma migrate deploy`, як і для попередньої фічі архівації).

Жодних інших змін схеми не потрібно: і "діловоди" (чотири
`PositionType` зі `scope=HURTOK`: `HURTKOVYI`, `SUDDIA`, `PYSAR`,
`SKARBNYK`), і призначення виховника (`VykhovnykHurtok`) вже існують.

## Налаштування гуртка (модальне вікно)

Відмова від структури зі скріншота (дві окремі кнопки "Призначити/
замінити провід" і "Закрити діловодення") на користь одного уніфікованого
списку з 5 рядків — Виховник, Гуртковий/а, Суддя, Писар, Скарбник. Кожен
рядок показує поточного утримувача (або "—") і дві дії: select для
призначення/заміни (лише з юнаків/виховників, вже привʼязаних до цього
гуртка) і кнопка "Зняти". Один механізм замість двох, бо бекенд уже має
для цього єдині примітиви:

- **Виховник:** `POST /vykhovnyk-assignments` (`{ vykhovnykId, hurtokId
  }`, ZVYAZKOVYI-only, вже існує) для призначення; `DELETE
  /vykhovnyk-assignments/:id` для зняття. На відміну від посад,
  `VykhovnykAssignmentsService.assign` **не** знімає автоматично
  попереднього виховника (many-to-many без заміни) — тож "замінити"
  в інтерфейсі означає дві послідовні дії фронтенду: спершу `DELETE`
  старого запису (якщо він є), потім `POST` нового. Вибір обмежено
  одним виховником на гурток лише на рівні інтерфейсу для простоти
  (бекенд технічно дозволяє кілька — якщо колись знадобиться, це вже
  підтримується без змін бекенду).
- **Гуртковий/Суддя/Писар/Скарбник:** `POST /kurin-positions`
  (`{ userId, scope: 'HURTOK', positionType, hurtokId }`, ZVYAZKOVYI-only,
  вже існує, автоматично знімає попереднього утримувача цього слоту і
  попередню позицію юнака в цьому ж scope — транзакційно) для
  призначення/заміни; `DELETE /kurin-positions/:id` для зняття
  ("закрити діловодення" зі скріншота — це зняття без заміни).
  Призначити можна лише юнака, що вже є членом саме цього гуртка
  (існуюча перевірка `target.hurtokId !== dto.hurtokId` в
  `KurinPositionsService.assign`).
- **Дата заснування:** нове поле, редагується через новий ендпоінт (див.
  нижче).
- **Розформувати гурток:** викликає вже існуючий `PATCH
  /hurtky/:id/archive`. Кнопка **disabled** (не прихована — з текстом
  причини), якщо в гуртку лишився хоч один юнак (та сама передумова, що
  вже перевіряється на бекенді); бекенд — джерело істини, фронтенд лише
  дублює перевірку для UX.

Усе в модалці — ZVYAZKOVYI-only, як і всі перелічені ендпоінти вже є.

### Новий ендпоінт: редагування дати заснування

`HurtkyService` отримує метод `update(hurtokId, dto, actor)`:

```ts
async update(hurtokId: string, dto: UpdateHurtokDto, actor: CurrentUserPayload) {
  const hurtok = await this.prisma.hurtok.findUnique({ where: { id: hurtokId } });
  if (!hurtok || hurtok.kurinId !== actor.kurinId) {
    throw new NotFoundException('Hurtok not found in this kurin');
  }
  return this.prisma.hurtok.update({
    where: { id: hurtokId },
    data: { foundedAt: dto.foundedAt ? new Date(dto.foundedAt) : null },
  });
}
```

`UpdateHurtokDto`: `{ foundedAt?: string | null }` (ISO date string,
`@IsOptional() @IsISO8601()`). Контролер:

```ts
@Roles(Role.ZVYAZKOVYI)
@Patch(':id')
update(@Param('id') id: string, @Body() dto: UpdateHurtokDto, @CurrentUser() user: CurrentUserPayload) {
  return this.service.update(id, dto, user);
}
```

Назва (`name`) лишається нередагованою — не запитувалось, і зміна імені
зачіпає `slug` (генерується з імені), що додає ризик побитих посилань.
Поза межами цієї фічі.

## `getMembersBySlug` і списки — додати `foundedAt`

`HurtkyService.getMembersBySlug()` вже повертає `hurtok: { id, name,
slug, number, archivedAt }` — додати `foundedAt: hurtok.foundedAt`.
`listForKurin()` використовує `findMany` без `select`, тож нове поле
автоматично зʼявляється в результаті без змін коду бекенду.

## Frontend

### Спільний компонент таблиці гуртка

Зміст, який зараз є в `apps/web/app/[kurinNumber]/hurtky/[slug]/page.tsx`
(банер "Архівовано"/заголовок, кнопка "Налаштування", "Додати юнака/чку",
таблиця членів), виноситься у спільний компонент (наприклад
`HurtokDetailPanel`), що приймає `slug` і рендериться і зі сторінки
`/[kurinNumber]/hurtky/[slug]`, і з розгорнутого рядка акордеону на
`/hurtky` — без дублювання коду.

### `/hurtky` — акордеон

- Кожен рядок: назва + номер, кількість членів, імʼя виховника (якщо є),
  шеврон розгортання.
- Клік розгортає/згортає **саме цей** рядок; кілька рядків можуть бути
  розгорнуті одночасно (простий `Set<string>` розгорнутих slug'ів у
  локальному стані компонента).
- Розгорнутий вміст = `<HurtokDetailPanel slug={h.slug} />`.
- Для VYKHOVNYK-ролі список і далі фільтрується до призначених гуртків
  (як зараз); кнопка "Налаштування" в їхньому розгорнутому вмісті не
  показується (ZVYAZKOVYI-only, керується всередині `HurtokDetailPanel`
  за `session.role`).

### Модальне вікно налаштувань (`HurtokSettingsDialog`)

Нова UI-компонента (Dialog поверх сторінки, на базі вже використовуваних
`components/ui/*`), що приймає `hurtok`/`members`/`slug` і рендерить:
5 рядків призначення (виховник + 4 посади), поле дати заснування з
кнопкою "Зберегти" (`useUpdateHurtok` — новий хук), кнопку "Розформувати
гурток" (`useArchiveHurtok`, вже існує). Відкривається кнопкою
"Налаштування" в `HurtokDetailPanel`.

### Нові/змінені хуки (`apps/web/lib/queries/hurtky.ts`)

- `useUpdateHurtok(id)` — `PATCH /hurtky/:id`, інвалідує `['hurtky']` і
  `['hurtky', 'by-slug', slug]` (той самий патерн, що й
  `useArchiveHurtok`).

Призначення/зняття виховника й посад використовують уже наявні хуки з
`apps/web/lib/queries/vykhovnyk-assignments.ts` і
`apps/web/lib/queries/positions.ts` — нових хуків для них не потрібно.

### Типи (`apps/web/lib/types.ts`)

- `Hurtok.foundedAt: string | null` (нове поле).
- `HurtokMembers.hurtok.foundedAt: string | null` (нове поле).

## Явно поза межами цієї фічі (YAGNI)

- **Аватар/сильветка гуртка** — відкинуто користувачем, не робимо.
- **Перейменування гуртка** — не запитувалось, ризик для `slug`.
- **Кілька виховників на гурток в UI** — бекенд дозволяє, інтерфейс
  свідомо обмежує до одного для простоти; розширення — окрема майбутня
  розмова.
- **Строгий акордеон (один розгорнутий рядок за раз)** — користувач
  обрав "кілька одночасно".

## Тестування

- `apps/api/test/`: e2e на новий `PATCH /hurtky/:id` (успіх для
  ZVYAZKOVYI в межах свого куреня, 404 для чужого куреня, 403 для
  не-ZVYAZKOVYI, порожнє значення скидає `foundedAt` на `null`).
- `apps/web/e2e/`: Playwright-сценарії на акордеон (`/hurtky` розгортає
  рядок і показує членів; два рядки можуть бути розгорнуті одночасно) і
  на модалку налаштувань (зміна виховника, призначення/зняття посади,
  зміна дати заснування, "Розформувати гурток" disabled з юнаками й
  активний на порожньому гуртку) — за існуючим патерном
  (`seedKurinWithZvyazkovyi`, `loginAs`, `createHurtok`/`createUserAs`).
