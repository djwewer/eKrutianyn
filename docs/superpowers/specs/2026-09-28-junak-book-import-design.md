# Імпорт юнаків з "Книги судді" — дизайн-документ

## Контекст і мета

Курені ведуть "Книгу судді" — таблицю (Google Sheet) з повним переліком
юнаків, їхніх гуртків, псевдо, дат народження, ступенів проб, контактів
опікунів і посад. Мета цього підпроєкту: дати звʼязковому (і, за
потреби, курінному/судді) імпортувати цю таблицю в застосунок — не
вгадуючи автоматично структуру, а через ручний майстер мапінгу
стовпчиків — щоб наповнення нового куреня (або довнесення даних у вже
існуючий) відбувалося зручно, замість ручного одноразового введення
кожного юнака.

Підпроєкт також включає мінімальний **зворотний звʼязок**: коли новий
юнак після цього створюється звичайним шляхом у застосунку, і в куреня є
підключена й замаплена "Книга судді", застосунок дописує новий рядок у
таблицю — щоб таблиця й застосунок не розходились для нових юнаків.
Повна двостороння синхронізація (зміна ступеня/посади → оновлення рядка
в таблиці) **поза межами** цього підпроєкту — див. "Явно поза межами".

Підключення самої таблиці використовує ту саму per-kurin OAuth-
інфраструктуру, що й "Облік реманенту"
(`docs/superpowers/specs/2026-09-19-google-drive-oauth-design.md`) —
той самий `drive.file` scope, той самий Picker, той самий збережений
`driveRefreshToken` на `Kurin`. Додатково потрібно увімкнути Google
Sheets API в Cloud Console (ручний крок, `drive.file` scope це вже
покриває — нового OAuth-дозволу не потрібно).

## Явно поза межами цього підпроєкту

- Повноцінна вкладка "Книга судді" з беклогу (перегляд списку юнаків,
  ручна зміна ступеня Суддею) — окремий майбутній підпроєкт.
- Зворотна синхронізація змін ступеня/посади/контактів у вже існуючий
  рядок таблиці — лише **створення нового юнака** дописує новий рядок;
  жодні подальші зміни в застосунку не оновлюють вже наявні рядки.
- Розширення `PositionType` новими значеннями (наприклад, окремий тип
  для "Заступник Гурткового") — звʼязковий сам мапить такі текстові
  значення на вже наявні типи посад (наприклад, Суддя) під час Кроку 2.
- Автоматичне визначення структури таблиці (розпізнавання, яка колонка
  за що відповідає) — мапінг завжди ручний.

## Частина 1: Флоу користувача

1. Звʼязковий (або курінний/суддя) на сторінці `/kurin` тисне
   **"Імпортувати юнаків з Книги судді"**.
2. Обирає Google Sheet через Picker (той самий OAuth-клієнт, що й для
   реманенту; вигляд Picker налаштований на показ таблиць, а не папок).
3. Застосунок читає аркуш через Sheets API (`values.get` на весь діапазон
   з даними) і показує майстер:
   - **Крок 1 — Мапінг стовпчиків.** Список стовпчиків таблиці (за
     заголовком з першого непорожнього рядка) зліва, спадний список
     полів застосунку справа. Доступні цілі: Імʼя та прізвище (одним
     полем — перше слово стає `firstName`, решта після першого пробілу —
     `lastName`; якщо в клітинці лише одне слово, `lastName` лишається
     порожнім і рядок підсвічується на Кроці 3 як такий, що потребує
     ручного виправлення), Псевдо, Дата народження, Гурток, Email, Телефон, Дата
     досягнення ступеня "Прихильник"/"Учасник"/"Розвідувач" (3 окремі
     цілі), Діловодство в гуртку, Діловодство в курені, Контакт 1
     (імʼя/телефон/email — три під-поля), Контакт 2 (так само), або
     "Не імпортувати". Кожен стовпчик мапиться рівно на одну ціль (або
     жодну).
   - **Крок 2 — Мапінг значень посад.** Якщо на Кроці 1 замаплено хоч
     один стовпчик "Діловодство", збираються всі унікальні текстові
     значення з цих стовпчиків по всій таблиці (наприклад: "Гуртковий",
     "Скарбник", "Суддя", "Заступник Гурткового", "Нема") — і для
     кожного звʼязковий обирає відповідний `PositionType` або
     "Не імпортувати". Значення на кшталт "Нема" звʼязковий просто не
     мапить.
   - **Крок 3 — Перегляд і виправлення.** Таблиця з усіма рядками після
     застосування мапінгу з Кроків 1-2:
     - Стовпчик "Гурток" автоматично **протягнутий вниз** — порожні
       комірки заповнюються значенням з останнього непорожнього рядка
       вище (типова структура паперових/табличних книг судді, де назва
       гуртка вказана лише в першому рядку групи).
     - Повністю порожні рядки (немає навіть ПІБ) пропускаються
       автоматично, не показуються в переліку.
     - Кожен рядок, де бракує обов'язкового поля (email, або `lastName`
       — якщо ПІБ не розбилося на два слова, див. Крок 1), підсвічується
       — звʼязковий вписує значення вручну прямо в цій таблиці. Рядок з
       незаповненим обов'язковим полем не можна імпортувати, доки поле
       не заповнено.
     - Для кожного рядка застосунок підказує можливий **збіг** із уже
       існуючим юнаком куреня (приблизний пошук за
       імʼям+прізвищем+датою народження) — якщо знайдено, рядок
       позначений як "оновити {Імʼя Прізвище}", інакше — "новий юнак".
       Звʼязковий може вручну змінити рішення для будь-якого рядка
       (підтвердити інший збіг або примусово створити нового).
4. Тиснеш **"Імпортувати"**.

## Частина 2: Хто імпортує і як це узгоджується

- **Звʼязковий** — імпорт виконується одразу, без підтвердження (як і
  підключення Google Drive для реманенту).
- **Курінний або Суддя** — весь майстер (Кроки 1-3) проходить так само,
  але фінальна кнопка "Імпортувати" створює **один** запит на
  затвердження нового типу `BULK_IMPORT_JUNAKY` з усім розвʼязаним
  пакетом рядків усередині (`newData`). Звʼязковий бачить у списку
  запитів один запит "Масовий імпорт: N юнаків з Книги судді" з
  розгорткою переліку і одним рішенням підтверджує чи відхиляє **весь
  пакет разом** — не по рядку окремо.
- Схвалення виконує ту саму логіку створення/оновлення (Частина 4), що
  й прямий імпорт звʼязковим, просто відкладену до моменту підтвердження.

## Частина 3: Модель даних

```prisma
model Kurin {
  // ...наявні поля (включно з driveRefreshToken/driveFolderId з реманенту)...
  judgeBookSpreadsheetId   String?
  judgeBookSpreadsheetName String?
}

model JunakImportMapping {
  id                   String   @id @default(uuid())
  kurinId              String   @unique
  kurin                Kurin    @relation(fields: [kurinId], references: [id])
  columnMapping        Json
  positionValueMapping Json
  updatedAt            DateTime @updatedAt
}
```

`columnMapping` — масив об'єктів `{ column: string; header: string; field: string }`
(`column` — літера стовпчика, `field` — один із фіксованого переліку
цілей з Кроку 1). `positionValueMapping` — масив
`{ rawValue: string; positionType: PositionType | null }`.

`Kurin.judgeBookSpreadsheetId`/`Name` — окремий вказівник від
`driveFolderId`/`driveFolderName` (реманент) — курінь підключає Drive
один раз, але обирає окремі файли/папки для кожної фічі, як і було
закладено в дизайні OAuth-міграції.

Обидві зміни — нова таблиця й нові нульові поля на `Kurin` — чисто
додаткова міграція.

Розширення `ApprovalActionType` новим значенням `BULK_IMPORT_JUNAKY`.

## Частина 4: Обробка рядка при імпорті (спільна для прямого імпорту й підтвердженого запиту)

Кожен рядок обробляється **у власній транзакції**. Результат кожного
рядка (успіх/помилка з причиною) збирається в підсумок, що показується
після завершення — часткова невдача одного рядка не скасовує інші.

Для кожного рядка:

1. **Юнак.** Якщо рядок позначено як "новий" — `User.create` (роль
   `JUNAK`, обовʼязкові поля з мапінгу; якщо email не вписаний на Кроці
   3 — рядок узагалі не потрапляє на виконання, це вже перевірено в UI).
   Якщо позначено як "оновити {юнак}" — `User.update` тим самим `id`,
   **всі замаплені поля з непорожньою клітинкою перезаписуються**
   значенням з таблиці (таблиця вважається джерелом правди для базових
   полів). Порожня клітинка в замапленому стовпчику не стирає вже наявне
   значення в застосунку — трактується як "дані не внесені в таблицю",
   не як "очистити поле".
2. **Гурток.** Значення з (протягнутого) стовпчика "Гурток" шукається
   серед гуртків куреня за назвою; якщо не знайдено — створюється новий
   гурток із цією назвою.
3. **Контакти опікунів.** Для кожного замапленого контакту
   (імʼя+телефон+email) — якщо контакт із такою комбінацією імені вже є
   в юнака, оновлюється; інакше створюється новий `GuardianContact`.
4. **Посади.** Для кожного замапленого стовпчика "Діловодство" — текстове
   значення шукається в `positionValueMapping`; якщо є відповідність —
   призначається `KurinPosition` через наявний сервіс призначення
   позицій (той самий, що вже гарантує "одна позиція на скоуп",
   автоматично знімаючи попередню за потреби).
5. **Прогрес проб.** Для кожного із замаплених стовпчиків
   Прихильник/Учасник/Розвідувач, що має дату — якщо відповідний етап
   програми проб цього куреня ще **не** закритий у юнака, усі його
   пункти позначаються виконаними, а сам етап закривається (через наявні
   методи `ProbyProgressService`) з цією датою, автором дії —
   звʼязковий/курінний/суддя, що виконує імпорт (або, для відкладеного
   запиту, — той, хто його підтвердив). Якщо етап **вже** закритий у
   застосунку — рядок цей етап не чіпає (прогрес ніколи не знімається,
   лише додається). Стовпчик "Скоб" (якщо замаплений — насправді такої
   цілі не буде в переліку Кроку 1, оскільки в каталозі проб немає
   четвертого етапу) ігнорується.

## Частина 5: Зворотний запис при створенні одного юнака

`ApprovalRequestsService.approve()` для `CREATE_JUNAK` (наявний код,
без зміни основної логіки) — після успішного створення юнака: якщо в
куреня є `judgeBookSpreadsheetId` і збережений `JunakImportMapping`,
формується новий рядок (значення розставляються по стовпчиках згідно
мапінгу, стовпчики без відповідного поля лишаються порожні) і
дописується в **кінець** таблиці через Sheets API
(`spreadsheets.values.append`). Новий рядок не намагається потрапити у
"правильну" групу гуртка (візуальне групування в таблиці) — це вимагало
б розпізнавання меж груп і ризикувало б зламати ручне форматування;
рядок просто йде в кінець зі своїм гуртком, вказаним явно.

Якщо запис у таблицю не вдався (Google тимчасово недоступний, токен
відкликано тощо) — це не блокує й не відкочує створення юнака, лише
логується попередженням. Той самий принцип graceful-деградації, що вже
застосований для реманенту.

Це стосується лише одиночного створення через `CREATE_JUNAK` — масовий
імпорт нічого не дописує назад (дані й так прийшли з цієї таблиці).

## Частина 6: Бекенд — читання таблиці

Новий метод (поруч із `GoogleDriveService`, той самий per-kurin
OAuth-клієнт) для читання значень аркуша:
`readSheetValues(kurinId, spreadsheetId): Promise<string[][]>` — викликає
Sheets API (`google.sheets({version:'v4', auth: client}).spreadsheets.values.get`)
на весь заповнений діапазон першого аркуша. І симетричний
`appendSheetRow(kurinId, spreadsheetId, values: string[]): Promise<void>`
для Частини 5.

Picker на кроці вибору файлу переналаштовується показувати таблиці
(`google.picker.ViewId.SPREADSHEETS`) замість папок.

## Тестування

- **Backend e2e:** обробка рядка (Частина 4) — створення нового юнака,
  оновлення існуючого (перезапис полів), створення гуртка "на льоту",
  контакти опікунів, призначення посади через мапінг значень, бекфіл
  прогресу проб (окремо перевірити: не знімає вже закритий етап),
  часткова невдача одного рядка не впливає на інші. `BULK_IMPORT_JUNAKY`
  — створення запиту курінним/суддею, затвердження звʼязковим виконує
  ту саму логіку. Зворотний запис при `CREATE_JUNAK` — з фейковим
  Sheets-клієнтом (як `GoogleDriveService` у тестах реманенту), включно
  з випадком "запис не вдався, юнак все одно створений".
- **Playwright:** сам майстер мапінгу з живою Google-таблицею не
  тестується (зовнішній сервіс, аналогічно до Picker реманенту) —
  перевірка вручну на проді. Що можна покрити: `BULK_IMPORT_JUNAKY` у
  списку запитів звʼязкового (з мокнутими даними, без реального Sheets
  API).

## Обмеження (свідомі спрощення)

- Мапінг стовпчиків/значень посад зберігається **на курінь**, не
  версіонується — зміна мапінгу перезаписує попередній без історії.
- Дедублікація при імпорті — за приблизним збігом імені+дати народження,
  завжди з ручним підтвердженням; немає точного детермінованого ключа
  (email міг з'явитися лише під час імпорту).
- Зворотний рядок завжди йде в кінець таблиці, без спроби зберегти
  візуальне групування по гуртках.
- Немає обмеження на розмір таблиці/кількість рядків — для типового
  розміру куреня (десятки, не тисячі юнаків) продуктивність не є
  проблемою.
