# Гурток → юнак → проба: навігація та людяні URL — дизайн-документ

## Контекст і межі

Реальний вміст проби (128 точок, 3 рівні) щойно завантажено в прод. Наявна сторінка гуртка (`apps/web/app/hurtky/[id]/page.tsx`) була розрахована на тестовий плейсхолдер (1-2 точки) — вона рендерить усі точки всіх юнаків гуртка плоским нерозбитим списком на одній сторінці. З реальним обсягом це нечитабельно, особливо з прицілом на мобільний інтерфейс (заявлений намір користувача).

Мета — новий флоу: **гурток (список людей) → юнак (детальна сторінка) → проба (згорнуті категорії)**, і людяний URL для конкретного гуртка.

### Явно поза межами

- Мобільний/адаптивний дизайн як такий — це майбутній окремий підпроєкт; цей флоу лише готує структуру (менші, згортувані блоки), яка буде зручнішою для мобільного, коли до нього дійде черга.
- Керування посадами (Діловоди) з екрана гуртка — тут лише перегляд, призначення й далі відбувається на `/positions`.
- Слаг для самого куреня — курінь лишається `kurinId` (raw id) в URL.
- Список гуртків (`/hurtky`) — без змін, URL і логіка ті самі.

## Флоу навігації

1. **`/hurtky` (без змін)** — список гуртків куреня, клік веде на новий URL гуртка (нижче).
2. **Сторінка гуртка** — тепер список людей: ім'я, базова роль (Юнак/Виховник), і всі активні посади з Діловодів, які ця людина займає (курінного/гурткового рівня, незалежно від того, до якого саме гуртка посада прив'язана). Дані беруться з `KurinPosition` (уже існує з підпроєкту "Діловоди"). Клік на людину → `/users/[id]`.
3. **`/users/[id]` (існуюча сторінка)** — отримує новий блок **"Проба"**, видимий лише коли `user.role === 'JUNAK'`. Показує прогрес по точках, згрупований за рівнем і категорією.
4. **Блок "Проба"** — кожна категорія — згорнута картка, розгортається стрілочкою/плюсиком; можна розгорнути кілька одночасно (незалежні перемикачі, не ексклюзивний акордеон). Підтверджувати/знімати точки тут можуть **виховник і зв'язковий** (розширення наявного правила — зараз лише виховник).

## URL і слаги

Конкретний гурток переїжджає з `/hurtky/[id]` (raw UUID) на **`/[kurinId]/hurtky/[slug]`**:

- `kurinId` — як є, raw id (курінь не отримує окремого людяного слага в цьому підпроєкті).
- `slug` — транслітерована латинкою назва гуртка (наприклад, "Вовки" → `vovky`), обчислюється й зберігається в новому полі `Hurtok.slug` при створенні гуртка.
- Колізії в межах одного куреня (два гуртки з однаковою назвою) вирішуються числовим суфіксом: `vovky`, `vovky_1`, `vovky_2`.
- Для вже існуючих гуртків (прод має реальні дані) — одноразовий скрипт-бекфіл, за тим самим принципом, що й скрипт завантаження реальної проби (ручний запуск, не частина авто-міграцій).

Список гуртків (`/hurtky`) лишається на місці — курінь і так завжди свій, слаг там не потрібен.

## Бекенд

- **Схема**: `Hurtok.slug String?` (нове, адитивне поле; nullable, бо існуючі гуртки на проді ще без слага до бекфілу). Унікальність слага в межах куреня забезпечується на рівні застосунку (перевірка+суфікс при створенні), а не жорстким `@@unique` (nullable-поле в Postgres дозволяє кілька NULL одночасно — це саме те, що потрібно до бекфілу).
- **Новий ендпоінт** `GET /hurtky/by-slug/:slug` (курінь актора — неявно з JWT, як і всюди): повертає гурток + список людей (юнаки з `hurtokId` = цей гурток, і виховники з `VykhovnykHurtok` на цей гурток), кожен з базовою роллю і масивом активних посад (`KurinPosition`, без фільтра по scope — показуємо все, що людина займає). **Замінює** наявний `GET /hurtky/:id/board` (видаляється разом зі старою "дошкою точок" — старий формат відповіді (точки+прогрес усіх юнаків одразу) більше нікому не потрібен, бо прогрес тепер запитується окремо на `/users/[id]` через уже наявний `GET /junaky/:id/progress`).
- **Розширення прав підтвердження**: `POST/DELETE /junaky/:id/progress/:pointId/confirm|unconfirm` — з `@Roles(Role.VYKHOVNYK)` на `@Roles(Role.VYKHOVNYK, Role.ZVYAZKOVYI)`. Внутрішня перевірка "виховник призначений на гурток юнака" лишається тільки для виховника; зв'язковий проходить без цієї умови (як і зараз для читання прогресу — там уже немає ZVYAZKOVYI-специфічного обмеження).

## Фронтенд

- Нова сторінка `apps/web/app/[kurinId]/hurtky/[slug]/page.tsx` — список людей гуртка (замінює `apps/web/app/hurtky/[id]/page.tsx`, який видаляється).
- `apps/web/app/hurtky/page.tsx` — посилання на гурток оновлюються на новий формат URL (`/${session.kurinId}/hurtky/${h.slug}`).
- `apps/web/app/users/[id]/page.tsx` — новий блок "Проба" (видимий лише для `user.role === 'JUNAK'`), використовує наявний `useJunakProgress(id)` і наявний `useProbyProgram()`, рендерить згруповано за рівнем/категорією (як зараз `/proby/page.tsx`), але з розгортанням категорій (стрілочка/плюсик, кілька відкритих одночасно). Кнопки підтвердити/зняти видно для `session.role === 'VYKHOVNYK' || session.role === 'ZVYAZKOVYI'`.
- `/proby/page.tsx` (власна проба юнака) — не змінюється в цьому підпроєкті; можна пізніше уніфікувати з новим акордеон-компонентом, але це не обов'язково для поточної мети.

## Тестування

Бекенд (e2e): створення гуртка генерує унікальний слаг; колізія назв дає `_1`/`_2`; `GET /hurtky/by-slug/:slug` повертає юнаків і виховників з їхніми посадами; виховник без призначення на гурток отримує 404 (як і зараз); зв'язковий тепер може підтвердити/зняти точку (новий тест), виховник без призначення на гурток юнака — досі 403.

Фронтенд (Playwright): клік із `/hurtky` веде на новий URL з людяним слагом; клік на людину з гуртка веде на `/users/[id]`; на сторінці юнака розгортання категорії проби показує точки; зв'язковий бачить і використовує кнопку підтвердження.

## Обмеження (свідомі спрощення)

- Слаг не перерахунковується при перейменуванні гуртка — старе посилання може "осиротіти" при зміні назви (прийнятно, перейменування гуртків — рідкісна дія).
- Немає окремого людяного слага для куреня — лишається raw id в URL.
