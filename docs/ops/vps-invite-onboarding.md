# Деплой: онбординг за посиланням-запрошенням

Тепер нових користувачів (звʼязкових, виховників, юнаків, імпорт) створюють **без пароля**.
Кожен отримує лист із посиланням (діє 7 днів) і сам встановлює пароль на сторінці `/welcome`.
Веб-форми більше не надсилають пароль, тому **API має бути задеплоєний раніше за фронтенд**.

## Порядок

1. **Бекап** (як у `vps-stage1.md`): `/opt/plast-api/backup.sh`
2. **API на VPS** (спершу):

```bash
cd /opt/plast-api/repo && git pull
cd /opt/plast-api && docker compose up -d --build
```

Міграції окремо запускати **не треба**: `CMD` у `apps/api/Dockerfile` виконує
`npx prisma migrate deploy` перед стартом `node dist/main`, тож нові міграції
застосуються автоматично при старті контейнера. Перевірка:

```bash
docker compose logs api --tail 50   # має бути "All migrations have been successfully applied" (або "No pending migrations") і запуск Nest без помилок
```

(Якщо міграції все ж треба прогнати вручну: `docker compose exec api npx prisma migrate deploy`.)

3. **Фронтенд** (після того, як API піднявся): злити гілку в `main`, Vercel задеплоїть автоматично.

## Змінні оточення на VPS

Запрошення надсилаються поштою, тому на VPS (у `.env`/`docker-compose.yml` сервісу `api`) мають бути задані:

- `GMAIL_USER`
- `GMAIL_APP_PASSWORD`
- `FRONTEND_URL` (адреса Vercel-фронтенду, з неї будується посилання `/welcome?token=...`)

Якщо «забули пароль» уже працює, вони вже задані, нічого додавати не треба. Якщо ні: додайте і
перезапустіть `docker compose up -d`. Без них користувача буде створено, але лист не піде
(у відповіді `inviteSent: false`); тоді скористайтеся кнопкою «Надіслати запрошення ще раз».

## Що буде з наявними користувачами

Користувачі з тимчасовими паролями **працюють як раніше**: їхній пароль і прапорець
зміни пароля не чіпаються. Нове лише для тих, кого створять після деплою.

## Перевірка після деплою

1. Створіть тестового юнака: має зʼявитися «Запрошення надіслано на {email}», лист прийде з кнопкою «Встановити пароль».
2. Перейдіть за посиланням, задайте пароль: вхід відбувається одразу.
3. На сторінці незапрошеного користувача видно «Ще не активовано · запрошення надіслано {дата}» і кнопку повторної відправки.
